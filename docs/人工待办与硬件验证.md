    2. 使用万用表测量诱骗线输出端电压，确认在 9V~12V 范围内，极性正确（内正外负或标明红正黑负）。
    3. 将诱骗线正负极稳固接入微雪 Bus Servo Adapter 驱动板的 **VIN 与 GND 接线端子**。
    4. 将微雪驱动板的 **GND 引脚** 用杜邦线连接至树莓派的 **GND 引脚**（如 Pin 6 或 Pin 9），实现**基准电平共地**。
    5. 将微雪驱动板的串口接口（USB 端口直连树莓派 USB 口，或者 UART TX/RX 交叉连接树莓派串口）。
    6. 将总线舵机二维平台的排线接至微雪驱动板的串行总线端口（菊花链连接两只总线舵机）。
    7. **【绝对禁忌】**：绝对不能把诱骗线的 9V/12V 接到树莓派的 5V 或 3.3V 引脚！
  - **人工反馈**：________________________（实测诱骗线输出电压为多少伏？微雪板电源指示灯是否正常点亮？共地是否稳固？）

- [x] **任务 2：树莓派散热安装与健康检查复查**
  - **操作说明**：
    1. 在树莓派 4B 的 CPU、RAM、电源芯片表面贴装纯铝/纯铜散热片，固定 5V 散热小风扇。
    2. 树莓派独立使用官方 5V/3A Type-C 供电。
    3. 在树莓派终端运行：`python scripts/hw/healthcheck.py`。
  - **人工反馈**：✅ 历史通过。安装散热风扇后空载 CPU 温度由 46.2°C 降至约 38~40°C，供电正常无欠压。

- [x] **任务 3：微雪总线舵机双轴 ID 分配、扫掠与状态回读**
  - **操作说明**：
    1. 确认两只总线舵机的 ID。若两舵机出厂 ID 相同（本批实物确实都是 0），
       请一次只接一只，用 `python scripts/hw/bus_servo_setid.py --id 0 --set-id N` 改写。
    2. 检查串口设备名：本批为 `/dev/ttyACM0`（CH343 USB-CDC，**不是** `/dev/ttyUSB0`）。
    3. 在 `configs/default.yaml` 中配置 `servo.serial_port`、`baudrate` 与 `serial_rts`。
    4. 运行交互测试脚本：`python scripts/hw/bus_servo_probe.py`
    5. 菜单选择 `1`：执行两轴归中（Yaw=0°, Pitch=0°），观察云台是否正对前方水平。
    6. 菜单选择 `2`：执行水平偏航扫掠，确认左负右正方向。若相反，将 `yaw_sign` 改为 `-1`。
    7. 菜单选择 `3`：执行垂直俯仰扫掠，确认仰正俯负方向。若相反，将 `pitch_sign` 改为 `-1`。
    8. 命令行运行自动扫掠：`python scripts/hw/bus_servo_probe.py --sweep`，连续 5 轮观察发热与抖动。

  - **⚠ 实机踩坑记录（2026-11-21，全部实测，勿再重复踩）**：
    1. **波特率不是 1Mbps**：本批 SP-15S 出厂即为 **115200 bps**（波特率档位寄存器 `0x06 = 4`）。
       官方示例默认的 1Mbps 在本批舵机上**完全无应答（0/20 命中）**。
    2. **必须拉高 RTS**：该半双工适配器不拉高 RTS 时应答丢包率极高（实测 115200 下仅 1/12~7/12 命中）；
       拉高 RTS 后稳定 10/10。已在 `servo.serial_rts: true` 与 `ServoController` 中固化。
    3. **两颗舵机出厂 ID 都是 0**（同一地址）：一条命令两颗同时动，位置回读出现 `41471`/`31231`
       这类不可能数值 —— 这是半双工总线**同 ID 抢答冲撞**的典型症状，**不是舵机坏了**。
       解决：一次只接一颗，用 `scripts/hw/bus_servo_setid.py` 逐颗改写 ID。
    4. **驱动板被过压打伤的判断依据**：若抓到板载 MCU 打印 `App_IWDG_SystemReset`（独立看门狗复位），
       说明此前诱骗线 >15V 已损伤板子稳压电路，需更换驱动板。
    5. **舵机应答有时会出现"帧洪流"**（单次 Ping 收到上万个重复帧）：属该适配器回波特性，
       协议解析时**读到第一个合法帧就应立即 `reset_input_buffer()`**，否则会被淹没。

  - **人工反馈**：
    - ✅ 2026-11-21 串口链路打通：`/dev/ttyACM0` @ 115200 bps，RTS 拉高，Ping 命中 **10/10**。
    - ✅ 供电实测回读 **11.9 V**（额定 9~12.6V），正常。
    - ✅ 俯仰（Pitch）舵机 ID 已由 `0` 改写为 **`2`**；验证 Ping ID 2 = 10/10、Ping ID 0 = 0/10。
    - ✅ 水平（Yaw）舵机 ID 已由 `0` 改写为 **`1`**；验证 Ping ID 1 = 10/10、Ping ID 0 = 0/10。
    - ✅ **双轴独立控制验证通过**（两颗均已改 ID 后）：
      · 仅发 ID1 指令 → 只有水平轴动，俯仰轴静止；
      · 仅发 ID2 指令 → 只有俯仰轴动，水平轴静止；
      · 双轴同发 → 斜向联动正常。
    - ✅ 大幅度运动验证通过：±39.4°(1600/2500) 与中位 2048，指令应答均为 OK。
    - ✅ `bus_servo_probe.py --sweep` 双轴自动扫掠 5 轮通过，归中后安全释放扭矩。
    - 📌 当前总线状态：**仅 ID 1（Yaw）与 ID 2（Pitch）两颗，无 ID 冲突**。
    - ✅ 2026-11-22 方向符号与零位偏置标定通过：
      · `Yaw = -20°` 逆时针左转、`Pitch = +15°` 向上抬头 → `yaw_sign: 1`、`pitch_sign: 1` 确认无误；
      · 实测机械零位偏移后固化软件偏置：`yaw_offset_deg: 33.0`、`pitch_offset_deg: -17.0`；
      · 全行程限位实测 `Yaw [-90°, +90°]`、`Pitch [-30°, +45°]` 均精准到位（误差 ≤8 步 / 4096，供电 `11.9V`），全程无机械碰撞或走线干涉。
