## 0. 目标范围锁定与当前基线

### 0.1 最终实现效果（严格范围锁定）

本项目最终**仅实现**以下端到端功能效果：

1. **声音触发启动**：系统平时处于待机监听状态，检测到预设语音唤醒词（例如说：“**小爱同学**”）后启动响应；
2. **同步双麦初步测算方位并移动云台**：唤醒的同时，利用双麦硬件同步采集的语音信号初步测算声源水平方位角，驱动云台转向说话人方向；
3. **音箱语音回应**：云台触发转向的同时，通过音箱播放语音回应（例如：“我在”）；
4. **转过去后识别人脸**：摄像头转向声源方向到位后，对画面进行人脸识别（必要时辅以小范围微扫入画）；
5. **持续跟踪人脸转动云台**：识别到人脸后，持续跟踪人脸位置变化，实时驱动二维云台（水平 Yaw + 俯仰 Pitch）转动，使人脸保持在画面中央区域；
6. **前端实时画面显示**：将摄像头实时画面（可叠加简洁的人脸框与当前阶段标识）低延迟显示在 Web 前端页面。

## 1. 目标交互闭环与验收标准

### 1.1 端到端完整交互流程

```text
[1. 待机监听 (IDLE)]
  云台归中，前端已可观看实时画面；AC3104 双麦持续写入 2 秒双通道同步环形缓冲，
  本地离线唤醒词引擎持续监听 “小爱同学”。
        │
        ▼  人在 1.0~2.5 m 任意水平方向说出 “小爱同学”
[2. 同步测向 + 转向 + 音箱回应 (TURN_AND_RESPOND)]
  ├─ 从双通道环形缓冲回溯截取刚说完的 “小爱同学” 同步双声道语音段
  ├─ 经人声带通滤波 + VAD + GCC-PHAT 初步测算水平方位角 θ_audio
  ├─ 并发动作 A：驱动 Yaw 舵机快速转向 θ_audio 方位
  └─ 并发动作 B：音箱异步播放回应语音（如 “我在！”），期间屏蔽自回声误触发
        │
        ▼  云台转向到位并平息 0.3 s
[3. 到位人脸识别 (SEARCH_FACE)]
  摄像头对当前画面进行人脸检测：
  ├─ 立即识别到人脸 ──> 直接进入持续跟踪
  └─ 暂未入画（受粗测角误差影响）──> 在当前方位 ±20° 内做小幅平滑微扫寻人
        │
        ▼  识别到人脸
[4. 持续人脸跟踪 (TRACK_FACE)]
  持续计算人脸中心与画面中心偏差 (dx, dy)，
  死区 + 限幅比例控制实时驱动 Yaw + Pitch 双轴平滑转动，始终将人脸保持在画面中央。
  短暂遮挡时保持姿态等待续跟，默认一直持续跟踪（支持终端手动复位）。
        │
        ▼  全过程并发运行
[前端实时画面显示]
  浏览器打开 http://<树莓派IP>:8080 即可低延迟观看摄像头实时画面（带人脸跟踪框与状态栏）。
```

### 2.3 电气安全与已验证硬件铁律（2026-11-21 / 11-22 实测固化）

1. **动力电严格隔离**：诱骗线 12V 仅接入微雪驱动板 VIN/GND，**绝对禁止**接触树莓派任何引脚；树莓派 GND 与微雪板 GND 保持共地。
2. **总线通信已实测固化参数（2026-11-21，勿回改默认值）**：
   - 串口设备：`/dev/ttyACM0`（CH343 USB-CDC）；
   - 波特率：**`115200 bps`**（本批 SP-15S 出厂档位寄存器 `0x06 = 4`，1Mbps 完全无应答）；
   - 流控引脚：打开串口后必须拉高 **`RTS = True`、`DTR = False`**，否则应答严重丢包；
   - 舵机 ID：**`yaw_id = 1`、`pitch_id = 2`**（已由出厂双 0 改写完毕并消除抢答冲突）；
   - 帧解析保护：读到首个合法应答帧后立即清空输入缓冲，防止适配器回波“帧洪流”。
3. **双麦声卡已实测固化参数（2026-11-22，勿误按 WM8960 配置）**：
   - 实际芯片：**AC3104**（TI `TLV320AIC3104` 国产替代/同型号），I2C 地址 `0x18`（8-bit 寄存器），**不是 WM8960**；
   - 驱动与设备树：使用 Linux 内核 `tlv320aic3x` 驱动 + 自制设备树插件 `aic3104.dtbo`（绑定 `ti,tlv320aic3x @ 0x18` + `simple-audio-card` + I2S，并补充 `AVDD 3.3V` / `DVDD 1.8V` 虚拟稳压器）；
   - ALSA 声卡标识：`respeaker2micac [respeaker-2mic-ac3104]`（当前枚举为 `card 3`，代码中优先按卡名 `respeaker2micac` / `plughw:CARD=respeaker2micac,DEV=0` 匹配，避免重启后卡号漂移）；
   - 麦克风模拟输入路由：经 5 组 PGA 实测，板载双麦接在 **`LINE1L` / `LINE1R`**（左稳态有效值 203、右 307；`Mic3L/R` 与 `Line2L/R` 为死输入 5~6），需通过 `sudo alsactl store` 持久化该路由防止重启失效。

### 3.2 关键技术方案细则

#### 方案 A：离线语音唤醒（“小爱同学”）+ 同步双麦测向一体化

> **关键工程问题**：说出“小爱同学”约需 `0.8 ~ 1.2 s`，唤醒词引擎确认命中时这句话刚好说完。若命中后再开始录音，根本录不到人声。因此**必须采用「双通道同步环形缓冲 + 命中后回溯截取」机制**。

1. **双通道同步采集**：
   - 使用 `sounddevice.InputStream`（或 ALSA `plughw:CARD=respeaker2micac,DEV=0`）打开 **AC3104 声卡（`respeaker-2mic-ac3104`）**，输入路由固定为 `LINE1L / LINE1R`；
   - 采样率策略：优先直接以 `16000 Hz / 2 ch / int16 / blocksize=512`（32 ms）打开 `plughw`；若硬件底层锁死 `44.1 kHz` / `48 kHz`，则保持原生高采样率双通道采集（高采样率更利于短基线 GCC-PHAT 时间分辨率！），再对喂入 KWS 的单声道流做轻量抽取/重采样至 `16 kHz`；
   - 回调函数仅做极轻量拷贝，推入有界队列，绝不在回调内做推理或 FFT。
2. **双通道环形缓冲区（Ring Buffer）**：
   - 后台音频处理线程维护一个长度 **`2.0 s`**（32,000 采样点 × 2 通道）的定长双通道环形缓存，实时追加每一块双声道 PCM。
3. **离线中文唤醒词引擎（KWS）**：
   - **首选方案**：**`sherpa-onnx` 中文关键词唤醒（KeywordSpotter）**；
     - 理由：纯本地离线（零联网、零 API Key）、原生支持树莓派 ARM64 Linux、通过拼音热词文件即可自定义任意中文唤醒词（如 `x iǎo ài t óng x ué @小爱同学`）、流式逐块喂入、单核 CPU 占用低；
   - **备选方案**：`Porcupine`（需免费 AccessKey）或 `openWakeWord`；
   - **联调保底开关**：配置保留 `wake_mode: "kws" | "energy_debug"`，在测试硬件链路或离线仿真时可快速模拟唤醒触发。
   - **输入通道**：取左声道（或 `(ch0 + ch1) / 2`）归一化后流式送入 KWS。
4. **命中瞬间同步双麦测向（DoA）**：
   - 一旦 KWS 在时刻 $t_0$ 返回命中“小爱同学”：
     1. 立即从双通道环形缓冲中**回溯截取最近 `doa_window_s`（默认 `1.0 s`）的双声道原始同步 PCM**；
     2. 对左右两通道施加 **300 Hz ~ 3400 Hz 人声带通滤波**，滤除低频风扇轰鸣与高频干扰；
     3. 将该 1.0 s 语音切分为若干 64 ms 重叠短帧，筛选出 RMS 能量高于自适应门限的人声有效帧（简易 VAD），对每个有效帧计算 **GCC-PHAT + 抛物线亚采样插值**，取高置信度帧角度的**中位数**作为最终水平方位角 $\theta_{\text{audio}}$；
     4. 若强混响导致整体置信度低于阈值，自动平滑降级为左右声道能量差定侧别（左 `-35°` / 右 `+35°`）。
5. **底座固定式麦克风坐标系映射（防坑关键）**：
   - AC3104 双麦板插在树莓派 40-Pin GPIO 排针上，与桌面固定（**不随云台旋转**），因此双麦测算得到的 $\theta_{\text{audio}}$ 是**相对于底座正前方的绝对偏航角**；
   - 转向目标角直接按绝对角计算：`target_yaw = clamp(theta_audio + audio_zero_deg, min_yaw, max_yaw)`；
   - 配置中提供 `mic_mounted_on_gimbal: false`（默认底座固定；若后续把双麦改挂在云台上，改为 `true` 即自动切为 `current_yaw + theta_audio`）。

#### 方案 B：音箱异步语音回应与防自触发机制

1. **离线预置回应音频**：
   - 在 `assets/audio/wakeup_reply.wav` 放置预先生成/录制的清晰中文回应语音（如“我在！”或“你好，我在呢”），采样率与 AC3104 声卡兼容（`44.1 kHz` 或 `16 kHz / 48 kHz` WAV，通过 `plughw:CARD=respeaker2micac,DEV=0` 自动适配），确保零网络延迟、零 TTS 算力消耗。
2. **独立轻量放音适配器 (`src/pantilt/adapters/actuation/speaker.py`)**：
   - 提供 `play_async(audio_path)` 接口，后台线程调用 ALSA `aplay -D <playback_device>`（或 `sounddevice`）非阻塞播放；
   - 触发唤醒后，**先下发云台转向指令，紧接着调用 `speaker.play_async()`**，实现“一边转向、一边回应”。
3. **自回声抑制（杜绝音箱声音二次唤醒）**：
   - 状态机离开 `IDLE` 进入 `TURN_AND_RESPOND` 时，立即置位音频屏蔽标志并清空音频待处理队列；
   - 音箱放音期间及之后的整个跟踪阶段不消费唤醒事件；仅当系统回到 `IDLE` 且放音完全结束并经过 `0.5 s` 冷却期后，才重新允许 KWS 触发。

#### 方案 C：OV9281 灰度图人脸识别与持续双轴跟踪

1. **OV9281 单色灰度图像适配与检测器选优**：
   - OV9281 输出单色灰度图，在阶段 2 实机对比以下检测器并锁定最优默认方案：
     - **推荐首选：OpenCV `FaceDetectorYN` (YuNet ONNX)**——模型约 230 KB，OpenCV 原生接口，在树莓派 4B 上缩放至 `320×200` 推理可达 25~40 FPS，将灰度图转为 3 通道 BGR 输入后对单色画面鲁棒性强、侧脸/光照适应度远优于 Haar；
     - **对比备选：MediaPipe BlazeFace**——仓库 `vision.py` 已实现灰度转 RGB 路径，实机对比召回率与帧率；
     - **保底方案：OpenCV Haar Cascade**——零额外模型文件。
   - 视觉管线固定仅运行人脸检测（`target_mode: "face"`），关闭 ArUco 检测路径。
2. **多人脸与防抖稳态策略**：
   - **选脸连续性**：首次锁定时选画面中面积最大（最近）的人脸；连续跟踪期间优先选择与上一帧中心距离最近的有效人脸，避免背景路人经过导致云台乱跳；
   - **坐标轻量平滑**：对人脸中心像素偏差 $(dx, dy)$ 做轻度指数平滑（EMA，如 $\alpha = 0.6$），抑制单帧边界框微跳。
3. **持续双轴云台控制（死区 + 限幅比例控制）**：
   - 在现有 `DeadzoneStepController` 基础上，将纯固定步长升级为**死区 + 限幅比例步进**：
     - 若 $|dx| \le \text{deadzone\_px\_x}$（初值 `25 px`），水平增量为 `0`；否则 $\Delta\text{yaw} = \text{clip}(k_{p,x} \cdot dx,\ -\text{max\_step\_yaw},\ +\text{max\_step\_yaw})$；
     - 若 $|dy| \le \text{deadzone\_px\_y}$（初值 `20 px`），俯仰增量为 `0`；否则 $\Delta\text{pitch} = \text{clip}(k_{p,y} \cdot dy,\ -\text{max\_step\_pitch},\ +\text{max\_step\_pitch})$；
   - 效果：人脸离中心远时追得快，靠近中心自动减速平稳停进死区，避免高频来回拉扯抖动；严格遵守双轴软件限位（Yaw `[-90°, +90°]`，Pitch `[-30°, +45°]`）。
4. **到位微扫寻人与“一直跟踪人脸”保持策略**：
   - **到位寻人 (`SEARCH_FACE`)**：转向到位后若未立刻看到人脸（例如双麦粗测有 ±15° 误差），云台以当前偏航角为中心，按小步幅在 `[θ - 20°, θ + 20°]` 范围平滑微扫一轮；只要任意一帧识别到人脸，立刻中止微扫切入 `TRACK_FACE`；若整轮微扫结束（如 4~5 秒）仍未找到人脸，则安全归中回 `IDLE` 等待下次唤醒。
   - **一直持续跟踪 (`TRACK_FACE`)**：
     - 一旦进入 `TRACK_FACE`，系统持续跟踪人脸移动并转动云台；
     - 当人脸短暂离开画面或被手/物体遮挡时，云台**保持在最后位置等待**，一旦人脸重新出现立即无缝继续跟踪；
     - **默认不因短暂丢脸自动回中放弃**（配置 `lost_timeout_s: 0` 表示永不自动退出跟踪，始终保持等待/跟踪；如需演示复位，支持终端按 `c` 归中回到 `IDLE`，或可选配置较长超时如 `60 s`）。

### 阶段 4：持续人脸跟踪控制器与 4 态主控状态机改造

**阶段目标**：完成视觉纯人脸跟踪、双轴平滑控制与 4 态状态机串联，实现“唤醒转向 + 音箱回应 → 转过去识别人脸 → 持续跟踪人脸转动云台”的完整控制逻辑。

- [ ] **任务 4.1：视觉管线聚焦人脸检测与连续性优化**
  - 精简 `src/pantilt/adapters/perception/vision.py`，默认锁定 `face` 模式并接入阶段 2 选定的最优检测器（如 YuNet / MediaPipe）；
  - 实现多人脸场景的「主目标锁定 + 防跳脸距离门控」及 $(dx, dy)$ 轻度平滑滤波。
- [ ] **任务 4.2：双轴死区 + 限幅比例平滑控制器升级**
  - 升级 `src/pantilt/domain/controller.py`：保留死区静默防抖，死区外改为按像素偏差成比例限幅输出 $(\Delta\text{yaw}, \Delta\text{pitch})$；
  - 在真机上通过人脸移动实测调优 `deadzone_px_x/y`、`kp_yaw/pitch` 与 `max_step_yaw/pitch`，确保跟得上且停得稳。
- [ ] **任务 4.3：4 态状态机重构（移除激光与 ArUco）**
  - 重构 `src/pantilt/domain/state_machine.py` 为 `IDLE -> TURN_AND_RESPOND -> SEARCH_FACE -> TRACK_FACE`：
    - `IDLE`：监听唤醒词，命中即下发 Yaw 目标角与音箱回应标志，切入 `TURN_AND_RESPOND`；
    - `TURN_AND_RESPOND`：屏蔽音频，等待云台到位并平息 0.3 s 后切入 `SEARCH_FACE`；
    - `SEARCH_FACE`：持续检查人脸观测，见到人脸立即切入 `TRACK_FACE`；若超时仍未入画则先执行局部 `±20°` 微扫寻人，仍无人脸才回中归回 `IDLE`；
    - `TRACK_FACE`：持续驱动双轴（Yaw + Pitch）跟踪人脸；人脸短暂丢失保持原位等待续跟，默认一直保持跟踪态（不因短时遮挡回中）。
- [ ] **任务 4.4：主控应用装配更新与离线自动化测试**
  - 更新 `src/pantilt/application/tracker.py` 与 `src/pantilt/bootstrap.py`，接入 `SpeakerAdapter`，移除 `LaserIndicator` 依赖；
  - 更新/补充 `tests/` 下的状态机与控制器离线单元测试，覆盖「唤醒并发回应」「到位立即可见人脸」「到位微扫寻人」「持续跟踪与短暂遮挡续跟」「无激光调用」全部场景。

**阶段 4 门禁**：
- [ ] 离线 `pytest` 全部测试通过。
- [ ] 真机单测跟踪：人脸入画后左右走动、起立下蹲 2 分钟，云台持续平滑跟随不脱靶、居中不抖动，遮挡 3 秒后移开立即续跟。

## 5. 风险点与务实保底预案

| 风险点 | 可能现象 | 应对与保底预案 |
| :--- | :--- | :--- |
| **唤醒词模型在树莓派上误触发或漏触发** | 室内正常聊天误唤醒，或 2 m 外叫“小爱同学”不响应 | 优先使用 `sherpa-onnx` 离线中文 KWS，针对实测麦克风增益微调 `keywords_score` / `keywords_threshold`；必要时前置轻度音量门控或缩短测试距离至 1~2 m |
| **短基线双麦（65mm）在混响室内测角偏差大** | GCC-PHAT 测出的角度偏离 15°~25°，云台转过去人脸刚好在镜头外 | 1. 仅对 300~3400 Hz 人声有效帧做多帧中位数 GCC-PHAT；2. 低置信度降级左右能量差定侧别（±35°）；3. 依托 `SEARCH_FACE` 的 `±20°` 局部微扫兜底把人脸拉入画 |
| **音箱回应声被双麦拾取造成二次误唤醒** | 播放“我在”瞬间又触发一次唤醒或测向异常 | 触发后状态机立即离开 `IDLE`，放音期间与整个跟踪阶段均暂停消费唤醒词；回 `IDLE` 前强制清缓冲并加 0.5 s 冷却期 |
| **OV9281 单色灰度画面影响人脸检出率** | 暗光或侧脸下 MediaPipe/Haar 漏检 | 阶段 2 实机对比优先选用对灰度图更鲁棒的 OpenCV YuNet（灰度转 BGR + 可选 CLAHE 局部对比度增强）；同时保证演示现场基本正面照明 |
| **持续跟踪时画面边缘抖动或云台过冲** | 人站着不动时舵机微抖，或快速移动时来回画圈 | 采用死区（±25 px / ±20 px）+ 限幅比例控制 + 人脸中心 EMA 平滑；控制周期固定 20~30 Hz，并校核总线舵机实际减速比 |
| **AC3104 重启后 ALSA 路由复位或声卡编号漂移** | 重启树莓派后录音静音、变死输入或 `plughw:3,0` 找不到设备 | 1. 固定使用 `sudo alsactl store` 并在启动前校验 `LINE1L / LINE1R` 路由；2. 配置文件与命令统一按卡名 `respeaker2micac`（`plughw:CARD=respeaker2micac,DEV=0`）寻址，避免硬编码 `card 3` |
| **前端视频推流与视觉/语音争抢树莓派 CPU** | 同时跑 KWS + 人脸检测 + MJPEG 时帧率跌破 15 FPS | 人脸检测在缩放图（320×200）执行；MJPEG 限频 20~25 FPS、质量 75、限制最大并发连接 ≤2；彻底裁撤原复杂前端轮询与高频 SSE |

## 6. 执行铁律

1. **严守范围边界**：一切开发与测试严格服务于「语音唤醒（“小爱同学”）→ 双麦同步测向转向 + 音箱回应 → 转过去识别人脸 → 一直跟踪人脸转动云台 → 前端实时显示画面」，绝不重新引入激光、ArUco、ESP32 与复杂遥控功能。
2. **保护已验证的硬件基线**：沿用实测固化参数——总线舵机（`/dev/ttyACM0 @ 115200 bps, serial_rts=true, yaw_id=1, pitch_id=2`）、双麦声卡（AC3104 / `tlv320aic3x` + `aic3104.dtbo`、`respeaker2micac`、`LINE1L/LINE1R` 路由）以及独立大电流供电隔离方案。
3. **先单点真机验证，再集成写代码**：先在树莓派上独立验证 AC3104 双麦测向/放音、音箱出声、OV9281 灰度人脸检测与“小爱同学”唤醒，再进行主程序改造。
4. **音视频与控制解耦非阻塞**：音频采集回调零重运算，音箱回应必须异步播放，所有状态超时与周期严格使用 `time.monotonic()` 单调时钟。
5. **在现有分层上做减法与聚焦**：复用现有 `domain / application / adapters / infrastructure` 清晰结构，只做精简聚焦与目标改造，不推倒重来。
