## 2026-11-21 · 总线舵机串口链路实机打通与 ID 重新分配（俯仰轴 0 → 2）

### 一、问题现象
`scripts/hw/bus_servo_probe.py` 完全无响应：Ping 全 ID 扫描无任何应答帧。

### 二、逐层排查（共 6 轮，脚本沉淀为 `scripts/hw/bus_servo_diag.py`）

| 层次 | 检查项 | 结果 |
| :--- | :--- | :--- |
| USB 枚举 | `lsusb` / `/dev/ttyACM0` | ✅ `1a86:55d3` CH343 USB-CDC 正常 |
| 串口参数 | 8N1 / 无流控 / CTS | ✅ 端口可正常打开 |
| 波特率 × ID 全扫 | 10 种波特率 × ID 1~20 | ❌ 官方默认 1Mbps 完全无应答 |
| 广播 Ping | 空闲监听 1.2s | ❌ 总线主动发言为空 |
| 波特率精扫 | 9600 ~ 1000000 共 13 档 | ✅ **仅 115200 有应答** |
| 寄存器回读 | 型号 / 电压 / 温度 | ✅ `MODEL=777`（ST 系列）、`VOLT=119` → **11.9V** |

### 三、根因（三条，均为本批硬件的真实特性）

1. **波特率不是 1Mbps，而是 115200 bps**
   波特率档位寄存器 `0x06 = 4`，查表即 115200。官方示例默认 1Mbps 在本批实物上零应答。

2. **半双工适配器必须拉高 RTS 才能稳定收应答**
   实测对照（同一颗舵机，各 12 次 Ping）：

   | RTS | DTR | 应答命中 |
   | :---: | :---: | :---: |
   | 0 | 0 | 1/12 |
   | 0 | 1 | 3/12 |
   | **1** | **0** | **7/12 ~ 10/10** |
   | 1 | 1 | 3/12 |

   该设置已固化为配置项 `servo.serial_rts: true`，并在 `ServoController.__init__`
   打开串口后立即应用（同时 `dtr = False`，并增加 0.3s 总线稳定等待）。

3. **两颗舵机出厂 ID 都是 0（同一地址冲突）**
   症状：一条命令两颗同时动；位置回读出现 `41471`、`31231` 这类超出 0~4095 的值；
   单次 Ping 偶尔收到 1.8 万个重复帧 —— 均为半双工总线**同 ID 抢答冲撞**的典型表现。

### 四、解决与验证

用新增脚本 `scripts/hw/bus_servo_setid.py` 单独改写 ID（顺序：解锁 `0x37=0` → 写 `0x05=新ID` → 上锁 `0x37=1`）：

```
[1/6] Ping ID=0 命中 10/10
[2/6] 改前 MODEL=777  ID=0  BAUD档位=4  VOLT=119(11.9V)
[3/6] 解锁 EEPROM            ✅ OK
[4/6] 写入新 ID = 2          ✅ OK
[5/6] 以新 ID 上锁           ✅ OK
[6/6] Ping ID 2 = 10/10 ；Ping ID 0 = 0/10 ；ID 寄存器回读 = 2
```

大幅运动验证（`pitch_id=2`）：中位 2048 / +39.7°(2500) / -39.4°(1600) / 回中，指令应答全部 OK。
通过 `ServoController` 高层接口 `set_angles(pitch=10.0)` 联动测试亦正常。
